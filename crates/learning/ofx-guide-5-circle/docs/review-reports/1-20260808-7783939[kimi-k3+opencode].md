# Review: `ofx-guide-5-circle`

Overall: the crate **compiles cleanly** (`cargo clippy -p ofx-guide-5-circle
--all-targets` and `cargo build --release -p ofx-guide-5-circle` are both
warning-free), and it is a **faithful port** of the OFX guide's Example 5
"Circle" (`Documentation/sources/Guide/Code/Example5/circle.cpp` in the
vendored openfx tree), extended with the machinery the example exists to
demonstrate: spatial double params with a declared default coordinate system
(`radius`, `centre`; `src/lib.rs:289–326`), host-capability negotiation at
load time (API ≥ 1.2 gate, multi-resolution probe; `src/lib.rs:171–214`), a
conditionally defined `growRoD` boolean param (`src/lib.rs:336–346`), the
`GetRegionOfDefinition` action (`src/lib.rs:406–464`), and an `IsIdentity`
with a circle-outside-RoD test (`src/lib.rs:466–524`).

It also absorbs the fixes from the earlier reviews:

- **Both images are fetched via `make_clip_image_managed`**
  (`src/lib.rs:583–590`), so `clipReleaseImage` runs on every path including
  error paths — the guide-2 review's #1 cannot recur.
- **No panic sites across the FFI boundary** — the only `unwrap`-family call
  in `src/` is an infallible `unwrap_or_default` on a `Result<c_int>`
  (`src/lib.rs:201`); mutex poisoning and null pointers map to error codes.
- Abort-on-render returns `Ok(())` (`src/processing.rs:31–40`), not
  guide-2's `Err(kOfxStatOK)` sentinel, and `Box::into_raw` in
  `CreateInstance` is balanced by a `Box::from_raw` drop on the
  `prop_set_pointer` error path (`src/lib.rs:380–388`).
- The redundant null-check + `&*ptr` instance-data dance triplicated in
  guide-4 (its nit #3) is collapsed into the new
  `SharedDataHelper::get_instance_data` helper (`src/lib.rs:419,478,551`).
- The guide-3 `IsIdentity` regression class is **not** repeated: the radius
  epsilon keeps the reference's plain comparison (`radius < 0.0001`,
  `src/lib.rs:487`, matching `circle.cpp:880`).

It even fixes a bug in the C++ original: the reference sets the colour
param's hint on `centreParamProps` (`circle.cpp:532`), clobbering centre's
own hint and leaving colour with none; the port sets both hints on the
correct params (`src/lib.rs:325,333`).

Issues below are ranked by severity.

---

## 1. `Alpha` component support dropped on both clips (most important)

`src/lib.rs:278–284`:

```rust
props.prop_set_string_n(
    kOfxImageEffectPropSupportedComponents,
    &[
        kOfxImageComponentRGBA.as_ptr(),
        kOfxImageComponentRGB.as_ptr(),
    ],
)?;
```

The reference supports **three** component types on both Output and Source:
`{kOfxImageComponentRGBA, kOfxImageComponentRGB, kOfxImageComponentAlpha}`
(`circle.cpp:416`, applied at `circle.cpp:420–435`). The pixel loop is
component-count generic (`src/processing.rs:76–85`), so Alpha images would
work exactly as in the C++ (the single channel blended toward
`colour_quantised[0]`), and guide-3's port kept Alpha when its reference had
it. As written, hosts cannot wire Alpha-only clips through the effect (e.g.
drawing a circle into a matte). Nothing in the crate or the commit history
records the omission as deliberate.

**Fix:** add `kOfxImageComponentAlpha` to the array (or record the deviation
as deliberate).

## 2. Circle colour is clamped to [0, 1] for float output — the reference deliberately doesn't clamp float

`src/lib.rs:635–649` passes `|v, min, max| v.clamp(min, max)` as the clamp
for **all three** depths, and `src/processing.rs:29` applies it
unconditionally:

```rust
let colour_quantised = colour.map(|c| clamp(from_f64(c * into_f64(max)), T::default(), max));
```

The reference's `Clamp<T, MAX>` returns the value unclamped when `MAX == 1`
("don't clamp floating point values", `circle.cpp:624–631`, applied at
`circle.cpp:656–659`). For float output the port therefore squashes
out-of-range colour components — super-white HDR colours above 1.0, or
negative ones, settable via API/animation even though the colour UI presents
0–1 — before blending, while the C++ blends toward the colour as given. (For
byte/short the two agree: Rust's `as` saturates, so cast-then-clamp equals
the C++'s clamp-then-cast, and NaN is handled better by the port.)

**Fix:** skip the clamp for the float arm (pass a no-op clamp), or record
the deviation as deliberate.

## 3. Minor nits

- **`blend`'s third parameter shadows the fn name** (`src/processing.rs:105`):
  `fn blend(v1: f64, v2: f64, blend: f64)` — same nit as guide-4's #3;
  rename the parameter to `amount` or `t`.
- **Const-correctness**: source pixels are read through `*mut T`
  (`src/processing.rs:64–74`); `*const` would better express intent. Same
  nit as guide-3's #4. No behavioral difference.
- **Render fetch failures don't consult `abort`** (`src/lib.rs:583–590`):
  the reference maps a failed image fetch to `kOfxStatOK` when the host is
  aborting (`circle.cpp:802–811`); the port always returns
  `kOfxStatFailed`. Harmless in practice (hosts ignore the status of a
  render they aborted) and shared with the sibling crates.
- **`api_version` is stored but never read** (`src/lib.rs:74–75`,
  `#[expect(unused)]`) — faithful to the C++ (`gAPIVersion` is also
  write-only after `LoadAction`), so arguably intentional; dropping the
  field would lose nothing.
- **Two `#[allow(clippy::too_many_arguments)]`** (`src/lib.rs:592`,
  `src/processing.rs:8`): `pixel_processing` now takes 13 arguments; the
  conversion-fn quartet (`from_f64`, `into_f64`, `clamp`, `max`) and the
  circle settings (`centre`, `radius`, `colour`) would bundle naturally into
  small structs, as suggested in guide-3's #4.
- **Crate-docs typo**: "initialzing" (`src/lib.rs:3`), inherited across the
  sibling crates.

## 4. Still present from earlier reviews (declined there; listed for completeness)

- **Plugin identifier vs icon filename**: `pluginIdentifier` is
  `c"org.openeffects:CircleExamplePlugin"` (colon — faithful to the guide,
  `src/lib.rs:61`), but the bundled icon is
  `org.openeffects.CircleExamplePlugin.png` (dot —
  `xtask/src/learning_ofx_guide_5_build_plugin.rs:18`;
  `build/OfxGuide5.ofx.bundle/Contents/Resources/…`). The OFX packaging spec
  requires the icon to be named `pluginIdentifier + ".png"`, so hosts
  implementing the convention will never find it. Same status as guides
  1–4.
- **`tracing::error!` in `set_host` is still a silent no-op** — the
  crate-docs TODO about initializing a tracing subscriber remains open
  (`src/lib.rs:1–5,126–131`), inherited unchanged from guides 1–4.

## 5. Things verified as correct (no action needed)

- `Describe` matches the guide: label, grouping, filter-only context,
  float/short/byte depths, `kOfxImageEffectRenderFullySafe`, host frame
  threading = 1 (`src/lib.rs:225–255`; `circle.cpp:354–403`). Unlike
  guide-4's #1, `Describe` and `DescribeInContext` are consistent here —
  both filter-only (the C++ comment claiming "a filter and a general
  effect" is stale; the code never set general).
- `Load`: three suites fetched; API ≥ 1.2 gate (`src/lib.rs:186–197`,
  `circle.cpp:329–341`) — returning `kOfxStatErrMissingHostFeature` instead
  of the reference's `kOfxStatFailed`, a deliberate and more informative
  deviation; a single-dimension `kOfxPropAPIVersion` is handled explicitly
  rather than over-read (`src/lib.rs:186–192`); the multi-res probe
  defaults to false on error like the reference (`src/lib.rs:199–202`,
  `circle.cpp:344–347`).
- `DescribeInContext`: rejects non-filter contexts with
  `kOfxStatErrUnsupported` (`src/lib.rs:269–272`) — stricter than the
  reference, which never checks, consistent with guides 3–4. Radius param
  `kOfxParamDoubleTypeX`, default 0.25, min 0, display 0–2, label, hint
  (`src/lib.rs:289–309`, `circle.cpp:445–483`); centre `Double2D` /
  `XYAbsolute`, default [0.5, 0.5] (`src/lib.rs:311–326`,
  `circle.cpp:485–513`); colour RGBA, default [1.0, 1.0, 1.0, 0.5]
  (`src/lib.rs:328–334`, `circle.cpp:516–535`); `growRoD` defined only when
  the host supports multi-res, default 0, label, hint
  (`src/lib.rs:336–346`, `circle.cpp:537–556`) — all matching except issue
  #1's component list.
- Deliberate host-quirk deviation is documented in code: DaVinci Resolve
  rejecting `kOfxParamPropDefaultCoordinateSystem` is tolerated via `.ok()`
  with an explanatory comment and TODO (`src/lib.rs:293–302,315–322`). Per
  `ofxParam.h:494–508` the property only affects interpretation of the
  **default value**, so the fallback is sound — on such hosts the effect
  loads with a sub-pixel default circle until the user touches the params.
  (The guide text itself marks normalised coordinates deprecated:
  `ofxExample5_Circle.rst:104–105`.)
- Instance data lifecycle: `Box::into_raw` in `CreateInstance` /
  `Box::from_raw` in `DestroyInstance`, caching both clip handles, the
  three param handles, and the conditional `growRoD` handle exactly as the
  C++ `MyInstanceData` does (`src/lib.rs:351–404`, `circle.cpp:563–620`).
  The unused `isGeneralContext` field is rightly dropped (the C++ sets it
  and never reads it).
- `IsIdentity`: the epsilon test, the grow-RoD guard, and the
  RoD-disjointness test all match (`src/lib.rs:487–516`,
  `circle.cpp:880–899`); the out-args protocol is right (`kOfxPropName` =
  `Source`, `kOfxStatOK` vs `kOfxStatReplyDefault`;
  `src/lib.rs:518–523`).
- `GetRegionOfDefinition`: the `f64::min`/`max` union is equivalent to the
  reference's four ifs (`src/lib.rs:451–456`, `circle.cpp:850–854`); the
  action replies default when not growing or when the host lacks multi-res
  (`src/lib.rs:411–415,436–438`) — the last guard replaces the reference's
  dispatch-time gate (`circle.cpp:952`) and additionally avoids the C++'s
  possible NULL `growRoD` dereference if a host calls the action anyway.
- Render loop fidelity: abort polled every 20 rows (`src/processing.rs:31–40`,
  `circle.cpp:663`); pixel → canonical mapping with pixel aspect ratio and
  render scale (`src/processing.rs:42,51`, `circle.cpp:666,676`); 1-pixel
  edge anti-aliasing via `radius - d` (`src/processing.rs:54–62`,
  `circle.cpp:685–699`); out-of-bounds source reads fall back to black
  (`src/processing.rs:64–74`, `circle.cpp:702` + `circle.cpp:113–122`);
  per-component blend over the output's component count including the alpha
  channel (`src/processing.rs:76–85`, `circle.cpp:705–709`); per-depth
  dispatch on the output image (`src/lib.rs:604–651`,
  `circle.cpp:766–795`); destination addressed once per row and advanced
  per pixel, with the impossible bounds-miss returning `kOfxStatFailed`
  instead of the C++'s NULL dereference (`src/processing.rs:45–48,85`).
- Arithmetic is `f64` throughout where the reference uses `float` — a quiet
  precision upgrade, visually identical.
- `Cargo.toml` (`cdylib`, workspace inheritance/lints), `justfile`, xtask
  wiring (`learning-ofx-guide-5-build-plugin`), `.gitignore` (`/build/`),
  no build artifacts or `.DS_Store` tracked — all consistent with the
  sibling crates.

---

**Bottom line:** a faithful, well-hardened port of the guide's fifth
example, with the earlier reviews' lessons applied and one C++ bug (the
centre/colour hint mix-up) fixed along the way. The only host-visible
fidelity gap is the **dropped `Alpha` component support** (#1); #2 is an
edge-case behavioral deviation for out-of-range colours on float output;
#3 is cleanup.
