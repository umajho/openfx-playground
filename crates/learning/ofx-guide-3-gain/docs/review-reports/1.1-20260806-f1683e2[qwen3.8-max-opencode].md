# Review (addendum): `ofx-guide-3-gain`

Complements report `1-20260806-f1683e2[kimi-k3].md`, whose findings (#1
missing `.abs()` in `IsIdentity`, #2 display max 1.0 vs 10.0, #3 dead `Sub`
bound) were independently re-verified against the vendored reference
(`Documentation/sources/Guide/Code/Example3/gain.cpp`) and confirmed. Two
additional trivial findings:

## 1. `applyToAlpha` label deviates from the reference

`src/lib.rs:254`:

```rust
param_props.prop_set_string(kOfxPropLabel, 0, c"Apply to Alpha")?;
```

The reference uses `"Apply To Alpha"` (`gain.cpp:294–297`). Purely cosmetic;
only affects the host's UI text.

## 2. Theoretical `Box` leak in `action_create_instance`

`src/lib.rs:286–288`:

```rust
let my_data_ptr = Box::into_raw(Box::new(my_data)) as *mut c_void;

instance_props.prop_set_pointer(kOfxPropInstanceData, 0, my_data_ptr)?;
```

If `prop_set_pointer` fails after `Box::into_raw`, the allocation leaks — the
`?` returns without reconstructing the `Box`. Only reachable if the host fails
a property set, so this is theoretical; same class of issue as the one flagged
for guide 1 (report `1-20260804-c19691e[kimi-k3].md`, §5). Fix, if desired:
reconstruct and drop the `Box` on the error path.
